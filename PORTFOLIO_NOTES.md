# Virtual Events Starter Kit — Provenance & Portfolio Checklist

The current README is the upstream Vercel/100ms virtual-event starter documentation, including claims about Next.js Conf 2020, 100ms, DatoCMS, multiple CMS options and scale. Treat those capabilities as upstream starter features unless a repository-specific delta is verified.

## 10 tasks
1. Identify the exact Vercel/100ms starter baseline and compare this repository against upstream.
2. Isolate personally authored commits/files and document only that delta as original work.
3. Preserve Vercel, 100ms and other upstream attribution and licensing.
4. Remove or clearly mark claims such as 40,000 attendees and 99.99% uptime as upstream context, not evidence from this fork.
5. Verify which CMS, auth, database and 100ms integrations were actually configured here.
6. Audit all event, CMS, OAuth and token environment variables before any deployment.
7. If custom event UX exists, capture it with fork-specific screenshots and explain the design/product changes.
8. Add tests only around custom registration, stage, schedule or interaction behavior that differs from upstream.
9. If essentially unchanged, archive/unpin and classify as virtual-event architecture learning infrastructure.
10. Do not count the starter's conference scale, integrations or production history as independently implemented product features.

## Portfolio value
Useful architecture and realtime-event learning evidence; low standalone portfolio value without a meaningful custom delta.
